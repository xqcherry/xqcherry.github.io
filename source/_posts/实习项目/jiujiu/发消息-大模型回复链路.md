链路：用户点发送 -> 前端显示流式回复 -> 后端保存 assistant 消息



## 前端先做乐观 UI

`app/conpentents/ChatClient.tsx`

入口在`sendMessage`，由异步函数 `async(overrideContent?: string) => {}`实现



实现：

1. 取输入框内容，空内容直接 return

2. 检查积分、游客轮次、录音状态、附件大小

   ```javascript
   if (shouldShowCreditExhaustionUi) { ... return; }
   if (isGuestTurnLimitReached) { ... return; } 
   if (isRecording) { await stopRecording(); }
   
   if (selectedFileIsZip && selectedExportFile.size > MAX_CHAT_EXPORT_FILE_BYTES) { ... return; }
   if (selectedFileIsImage && selectedExportFile.size > MAX_CHAT_IMAGE_FILE_BYTES) { ... return; }
   ```

3. 如果当前没有会话，先 ensureActiveSession() 创建会话

   ```javascript
   let sessionId = activeSessionIdRef.current;
   if (!sessionId) {
   	try {
   		sessionId = await ensureActiveSession();
   	} catch(err) {
   		console.error(err);
   		setChatError(...);
       	return;
   	}
   }
   ```

4. 立刻把两条本地消息塞进 messages

   - 一个本地 USER 消息

   - 一个空内容的本地 ASSISTANT 占位消息

     ```
     const localUser: MessageItem = {
     	id: createClientId(),
         role: "USER",
         content,
         createdAt: new Date().toISOString(),
         messageType: "TEXT",
         attachment: localAttachment,
     }
     
     const localAssistantId = createClientId(); //  临时Id，后续替换
     markPending(localAssistantId); // 标记这个气泡正在等待中
     // 🔥核心：立刻更新状态机的消息列表
     setMessage((prev) => {
     	const list = Array.isArray(prev) ? prev : [];
     	return [
     		...list,
     		localUser, 	// 塞入用户刚说的话
     		{
     			id: localAssistantId,
               	role: "ASSISTANT",
               	content: "",
               	createdAt: new Date().toISOString(),
               	messageType: "TEXT",
     		}
     	];
     })
     scrollToBottomIfNeeded(); // 强制滚动到屏幕最下方
     ```

5. 这样用户一点击发送，界面马上看到自己的消息和一个等待中的 assistant 气泡，不用等后端返回



## 后端先只保存用户消息，不调用大模型

`/aichat/chat/ChatService.java`

```java
@PostMapping("/sessions/{sessionId}/messages")
public ChatDtos.CreateMessageResult createMessage(...)
```

通过`session cookike` 获取用户

`UUID userId = AuthUtils.requireUSerId();`

调用service层

`chatService.createUserMessage(userId, sessionId, request.content())`

1. `requireOwnedSession` 校验这个会话属于当前用户，并且在当前 active profile 下
2. 创建一条 `ChatMessageEntity`：
   - role = USER
   - content = content.trim()
   - messageType = TEXT
3. 保存到 chat_messages表
4. 返回 userMessageId 给前端



## 前端拿到 userMessageId 后打开 SSE

`app/conpentents/ChatClient.tsx`

这里用的是 SSE，不是 WebSocket。浏览器保持一个 GET 连接，后端可以不断推事件

```
const stream = new EventSource(...);
```

前端监听事件

- chunk：模型文本片段
- ai_error：模型调用失败
- done：本轮结束
- assessment_cta、pua_alert、pua_message、session_title：附加业务事件

监听到的chunk数据单独解析



## 后端 SSE 入口启动异步回复流程

`app/conpentents/ChatClient.tsx`

```java
@GetMapping(value = "/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public ResponseEntity<SseEmitter> stream(...)
```

1. `AuthUtils.requireUserId() `校验登录
2. resolveReplyAttachmentPayloadForStream(...) 取附件上下文，如果这条用户消息带上传文件
3. 创建 `SseEmitter`，超时 3 分钟
4. 包装成` SseChatReplyOutput`
5. ` CompletableFuture.runAsync(...)` 异步调用

HTTP 线程快速返回 SSE 连接，大模型调用在后台线程里跑



## Orchestrator 是主编排器

`aichat/chat/reply/ChatReplyOrchestrator.java`

1. 校验session属于用户，并确认 messageId 是这次的 USER 消息
2. 前置意图检测与快速响应：如果用户像是在要求测评，可能直接保存并推送 `assessment_cta`，不走普通大模型回复
3. PUA检查异步启动，和主回复并行跑
4. 前置余额检查，积分不足会抛异常
5. 通过`chatContextBuilder`构造大模型上下文
6. 通过 `ChatReplyAiExecutionResult`调用 AI,前端SSE展示
7. AI 完整返回后保存 assistant 消息，如果发现余额不足，把数据库内信息delete，反之正常返回
8.  善后处理与风险安全带：智能标题生成，同步等待pua检测结果，



### 上下文怎么拼给大模型

`aichat/chat/reply/ChatContextBuilder.java`

组装成一组 AiMessage

1. 从数据库取最近 N 条消息
2. 过滤掉不适合作为模型历史的消息，比如pua_image, cta
3. 把历史信息组装成 AiMessage
4. 如果用户消息带图片，会把最新user信息转成多模态的parts
5. 注入 persona system prompt,基础系统人设
6. 注入严格语言指令，确保语言输出正确
7. 注入memeory，只有profile开了memory且active memo points 时才注入
8. 注入relationship weather，如果有最新 weather score，会作为 soft context 注入
9. 如果上传的是聊天导出 ZIP，会注入附件上下文
10. 如果 RAG 开启，会拿最新用户问题去检索， 检索结果会被 RagPromptBuilder 包成 system block

```
SYSTEM persona 系统人设
SYSTEM reply language 系统语言规则
SYSTEM memory 系统记忆注入
SYSTEM weather 系统亲密关心注入
SYSTEM uploaded archive context 用户上传的三方聊天
SYSTEM rag context 知识库检索上下文
USER/ASSISTANT recent chat history 最近的对话历史
```



### 模型调用和流式返回

比如，`Orchestrator` 选择了流式回复
```java
ChatReplyAiExecutionResult aiResult = aiExecutor.execute(new ChatReplyAiExecutionRequest(
          context,
          command.deliveryMode(), // 这里
          command.output()::onChunk
  ));
```

Adapter 调 aiService.stream

`aichat/chat/reply/DefaultAiExecutionAdapter.java`

随后 `AiHttpClient` 真正请求大模型

后端收到上游 SSE，再转发给前端

这两步都在`aichat/ai/AiHttpClient.java`



总的来说：

大模型供应商返回 `delta`

`AiHttpClient` 解析 `delta`

` DefaultAiExecutionAdapter` 缓冲后交给 `deltaSink`

`SseChatReplyOutput` 发送 `SSE event` 

前端 `EventSource` 收到 chunk，追加到 `assistant` 气泡



## SSE 事件怎么发给前端

SSE输出类是 `aichat/chat/reply/SseChatReplyOutput.java`

定义事件：

```
onChunk       -> event: chunk
onCompleted   -> event: done
onError       -> event: ai_error
onSessionTitle -> event: session_title
onAssessmentCta -> event: assessment_cta
onPuaAlert    -> event: pua_alert
onPuaMessage  -> event: pua_message
```

前端收到后更新本地 assistant 占位消息的内容，所以你看到的是“边生成边显示”



## 完成后怎么落库、刷新真实消息 ID

模型返回后，后端在`aichat/chat/reply/ChatReplyOrchestrator.java` 保存assistant

持久化存储

  - role = ASSISTANT
  - messageType = TEXT
  - content = finalContent
  - modelName
  - token usage

然后扣积分。如果扣费阶段发现积分不足，会删除刚保存的 assistant 消息

前端收到 done 后，会在 finally 里刷新消息列表

前端之前显示的是本地临时 ID，刷新后会用数据库里的真实 messageId 替换
