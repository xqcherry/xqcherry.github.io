## 上下文压缩时一般会保留哪些关键信息？如何判断哪些内容可以被丢弃？

1. 用户意图，所有原始用户消息、以及用户中途的纠正和偏好
2. 决策与理由，做过什么关键决策、为什么这么做，防止模型压缩后推翻已定方案
3. 踩坑记录，报错信息 + 修复方式，防止压缩后重蹈覆辙
4. 当前状态，正在做什么、待办任务、下一步计划

判断标准就一条：可再生即可丢弃
1. 文件内容 → 可重新 Read → 丢
2. 命令输出、搜索结果 → 可重跑 → 丢
3. 中间推理草稿 → 无独立价值 → 丢
4. 图片/文档 → 换成 [image] 占位符 → 丢
5. 丢弃 ≠ 删除，完整 transcript 留在磁盘，摘要里附上路径，模型需要细节时可以回读

## CC 是怎么进行实现的?

CC 的上下文压缩是一套分层机制
1. 第一层是微压缩：不走 LLM，直接把旧的 Read、Bash、Grep 这类工具的返回结果替换成占位符，只留最近几条。因为文件内容随时可以重新读，这些是最先可以丢的
2. 第二层是全量压缩，当 token 超过阈值--大约窗口的 93%--时触发。它发一次独立的 LLM 请求做摘要,明确要求保留用户意图、所有原始用户消息、关键决策、踩过的坑和修复方式、当前任务状态和下一步
3. 摘要完成后不是直接替换，还有一步恢复注入：把最近读过的文件、当前的 plan、用过的 skill 按预算重新注入回上下文，让模型不用重读就能继续干活
4. 最后有个兜底：完整对话留在磁盘 transcript 里，摘要末尾附上路径，模型需要被压缩掉的细节时可以回读
