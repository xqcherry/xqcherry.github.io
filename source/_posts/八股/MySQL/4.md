## MySQL 的索引类型有哪些？


按「数据结构」分类：B+tree索引、Hash索引、全文索引。

按「字段特性」分类：主键索引、唯一索引、普通索引、前缀索引

按「字段个数」分类：单列索引、联合索引

按「物理存储」分类：聚簇索引（主键索引）、非聚簇索引（二级索引）

## 讲讲B+树索引?

MySQL InnoDB 默认使用 B+ 树作为索引结构

1. 非叶子节点只存索引，叶子节点存数据/索引字段和主键值
2. 并且叶子节点通过链表连接，使得范围查询效率更高
3. 相比 B 树，B+树高度更低，磁盘 IO 更少范围查询效率更高

### 为什么 MySQL 使用 B+树，而不是二叉树？

因为二叉树高度较高，树高大小对于磁盘IO次数，磁盘 IO开销较大

### 为什么不用红黑树？

两个原因：
1. 红黑树虽然查询效率是 O(logN)，但是它是二叉树，数据量大的时候树高度较高，需要更多磁盘 IO
2. 红黑树一个节点只能存储一个 key，而 B+树一个节点可以存储多个 key，更适合磁盘存储

### 为什么不用 B 树，而使用 B+树？

1. B树所有节点都存数据，可能非叶子结束；B+树非叶子节点只存索引，可以存储更多 key，降低树高度
2. 同时叶子节点通过链表连接，范围查询效率高

## 什么是聚簇索引和非聚簇索引？

- 聚簇索引是索引和数据存储在一起的索引结构，在 InnoDB 中，主键索引就是聚簇索引，叶子节点保存完整数据
- 非聚簇索引也叫二级索引，叶子节点保存索引字段和主键值，需要通过主键再次查询数据，这个过程叫回表

### 什么是回表?

使用普通索引查询时，先通过二级索引找到主键 id，再根据主键 id 去聚簇索引中查询完整数据，这个过程叫回表

### 为什么 InnoDB 建议使用自增主键？

因为 InnoDB 使用聚簇索引，自增主键插入数据时只需要追加到最后，减少页分裂，提高插入效率

### 什么是覆盖索引？

查询需要的所有字段，都可以直接从索引中获取，不需要回表

### 什么是索引下推?

把原本需要回表后判断的查询条件，提前在索引层进行判断，减少回表次数

### 为什么联合索引可以实现覆盖索引？

联合索引的叶子节点保存了索引字段 + 主键值，可以包含查询需要的字段

## MySQL 中使用索引一定有效吗

索引失效的场景：
1. 不遵循最左匹配原则
2. 对索引字段进行计算或函数操作
3. LIKE 左模糊查询
    ```
    WHERE name LIKE '%张'
    ```
4. 索引字段进行了隐式类型转换，比如varchar变成int
5. WHERE 子句中，如果在 OR 前的条件列是索引列，而在 OR 后的条件列不是索引列，那么索引会失效

### 索引为什么不是越多越好？

索引会占用磁盘空间，增删改时需要维护索引，过多索引会降低写操作性能

## MySQL 最左前缀匹配原则是什么？

MySQL 最左前缀匹配原则指的是联合索引查询时，需要按照索引字段的顺序从最左侧开始匹配
比如联合索引(a, b, c)，可以支持a, a+b, a+b+c查询，但不能跳过 a 直接查询 b 或 c
中间字段缺失则索引失效

### 联合索引的原理是什么？

联合索引是将多个字段组合成一个索引，本质上是一棵 B+Tree
索引节点的 key 是多个字段组合，MySQL 会按照索引字段的顺序进行排序，先比较第一个字段，再比较第二个字段
因此查询时需要遵循最左前缀匹配原则，才能利用联合索引

### 创建联合索引需要注意什么？

1. 遵循最左匹配原则
2. 将区分度高，查询频率高的字段放在前面
3. 不要创建过多字段
