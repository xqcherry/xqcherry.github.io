## MySQL 索引下推是什么?

索引下推是 MySQL 5.6 引入的优化技术，能减少回表次数，提升查询效率。核心思路是把部分查询条件从 Server 层下推到存储引擎层，在引擎层就把不符合条件的数据过滤掉，不用再回表取完整数据。

以前的流程是： 引擎层用索引定位数据，把主键给 Server 层，Server 层回表拿完整数据再用剩余条件过滤。

有了索引下推： 引擎层直接用索引里的列过滤，不符合条件的压根不回表，大大减少 I/O。

索引下推主要用在联合索引上

没有索引下推： Server 层 → WHERE 条件过滤（所有数据先回表再过滤）
开启索引下推： Server 层 → 仅接收有效数据（引擎层提前过滤，减少回表）

### 索引下推和最左前缀匹配原则有什么关系？

索引下推是对最左前缀匹配的补充
比如联合索引 (a, b, c)，查询 where a = 1 and c = 3，按最左匹配原则只能用 a 定位，c 用不上索引查找。但有了索引下推，虽然 c 不能用来定位，但索引里存了 c 的值，引擎层可以直接过滤 c != 3 的记录，减少回表

### 为什么主键查询不需要索引下推？

因为主键索引的叶子节点直接存储完整数据行，查到就拿到全部数据了，压根不需要回表。索引下推解决的是"减少回表次数"的问题，主键查询没有回表这个环节，自然不需要优化
