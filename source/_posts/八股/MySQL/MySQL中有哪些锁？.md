## MySQL中有哪些锁？

MySQL InnoDB 的锁可以从两个维度来分：粒度和模式。

粒度上分：表锁和行锁。表锁锁整张表，行锁只锁具体的行，粒度越细并发越高。

模式上分：共享锁 S 锁和排他锁 X 锁。S 锁允许多个事务同时读，X 锁独占，读写都不让别人碰。

行锁又细分为三种：**记录锁**锁住具体那一行，**间隙锁**锁住两条记录之间的空隙防止插入，**临键锁**是记录锁加间隙锁的组合

### 共享锁 S 锁和排他锁 X 锁

在 MySQL 中，锁可以分为两大类

S锁（共享锁）：事务在**读取**记录时获取，允许多个事务同时持有S锁，互相不冲突。
X锁（排他锁）：事务在**修改**记录时获取，只允许一个事务持有X锁，其他事务必须阻塞等待。

S锁之间不冲突，但X锁与任何锁（S或X）都冲突。

`SELECT ... LOCK IN SHARE MODE;` 对记录加S锁。

`SELECT ... FOR UPDATE;` 对记录加X锁

MyISAM 引擎仅支持表锁，而 InnoDB 既支持表锁也支持行锁


### 元数据锁

元数据锁也分为读锁和写锁：

读锁（MDL_SHARED）：事务读取表元数据时获取（如SELECT），多个事务可同时持有，互不阻塞。
写锁（MDL_EXCLUSIVE）：事务修改表元数据时获取（如ALTER TABLE），会阻塞其他所有读写锁，确保独占访问

DDL：操作“表结构”的 SQL
DML：操作“表中数据”的 SQL

```
数据库
│
├── 表结构
│    └── DDL：CREATE / ALTER / DROP
│             ↓
│           MDL 写锁
│
└── 表数据
     └── DML：INSERT / UPDATE / DELETE
              ↓
            MDL 读锁
```


### 意向锁

当InnoDB加表锁时，需要判断表中是否存在行锁。如果逐条遍历记录检查，效率极低，因此引入了意向锁（Intention Locks）。

IS（Intention Shared Lock，共享意向锁）：对某行加S锁前，先在表上加IS锁，表明表内有S锁。
IX（Intention Exclusive Lock，独占意向锁）：对某行加X锁前，先在表上加IX锁，表明表内有X锁。

这样加表锁时，只需检查表上是否有IS或IX锁，无需遍历所有记录。

加表级S锁时，若表上没有IX锁，则可直接加。

加表级X锁时，若表上没有IX和IS锁，则可直接加。

IS和IX之间不会冲突，它们只是标记，用于快速判断


### 行锁的三种类型

记录锁（Record Lock）：锁住具体的索引记录。如果列没有索引，行锁会升级为表锁（全表扫描）。如果列有唯一索引且记录存在，则加记录锁；若为非唯一索引，可能加临键锁。

间隙锁（Gap Lock）：锁住两条记录之间的间隙，防止幻读。间隙锁之间不冲突，目的仅是阻止其他事务插入。

临键锁（Next-Key Lock）：记录锁 + 间隙锁，锁定一个左开右闭的区间（如 (3,5]）
