## MySQL 中事务隔离级别有哪些？

MySQL 事务隔离级别一共 4 种，隔离性从低到高分别是：读未提交、读已提交、可重复读、串行化

1. 读未提交：事务能看到别的事务还没提交的数据，等于毫无隔离可言。典型问题就是脏读，你读到的数据可能人家一会儿就回滚了，压根没落地。

2. 读已提交：只能看到别的事务已经提交的数据，脏读问题没了，但同一个事务里两次查同一条数据，结果可能不一样。这是不可重复读，Oracle、PostgreSQL、SQL Server 默认都是这个级别。

3. 可重复读：事务开始后，不管别的事务怎么改数据，你看到的只是开始那一刻的快照。MySQL InnoDB 默认就是这个级别，用 MVCC 实现。不过标准 SQL 定义里，这个级别还是会有幻读问题，就是两次范围查询返回的行数不一样。

4. 串行化：最严格的级别，相当于事务一个一个排队执行，等于把并发关了。InnoDB 在这个级别下会把普通 SELECT 自动加上共享锁，能彻底杜绝所有并发问题

### 主流大厂为啥选读已提交？

可重复读级别下 InnoDB 要维护更多的 undo log 版本链，长事务跑起来内存消耗大

可重复读的间隙锁范围更大，容易造成锁等待甚至死锁

业务上大多数场景其实不需要"同一事务内数据不变"这种保证，代码层面处理好就行
