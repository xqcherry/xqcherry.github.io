## MySQL 的覆盖索引是什么？

覆盖索引是指二级索引中已经包含了查询需要的所有字段，查询时直接从索引里拿数据，不用再回表去主键索引取完整数据行
本质上是一种查询优化，核心就是"索引里有"的数据就不去表里取了。能省掉回表这一步，I/O 少了，速度自然就上去了

### 覆盖索引的好处

1. 减少 I/O 操作，查询直接从索引拿数据

2. 避免回表，直接通过索引取值

3. 节省内存空间，索引只存储部分数据

4. 提高查询效率，减少 IO 次数

### 设计覆盖索引的技巧：

1. 高频查询优先：先分析业务里哪些查询执行频率最高，针对这些查询设计覆盖索引

2. 根据实际需求选择最常用的列

3. 利用联合索引：把 where 条件中的列放在联合索引的左边，可以提高查询效率

### 覆盖索引和索引下推有什么区别？

覆盖索引是完全不回表，索引里有查询需要的所有数据。索引下推是减少回表次数，把过滤条件下推到引擎层提前过滤，但最终还是要回表拿完整数据。两者解决的问题不一样，覆盖索引是"能不回表就不回表"，索引下推是"必须回表但少回几次"

### 一个查询既用了覆盖索引又用了索引下推，可能吗？

不可能。用了覆盖索引就不需要回表，索引下推解决的是减少回表次数的问题。覆盖索引的场景下，索引下推没有用武之地

### 怎么在不改业务代码的情况下让查询走覆盖索引？

加联合索引。分析慢查询日志，找出"频繁执行的查询"，把 where 条件列和 select 的返回列组合成联合索引。

比如查询是 select a, b from t where c = 1，加一个 (c, a, b) 或 (c, b, a) 的联合索引就能覆盖。不改 SQL，只加索引，对业务代码零侵入
