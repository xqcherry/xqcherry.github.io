## MySQL 的架构是怎么样的？

**MySQL 的架构共分为两层：Server 层和存储引擎层**

1. Server 层负责建立连接、分析和执行 SQL
2. 存储引擎层负责数据的存储和提取

## MySQL 的存储引擎有哪些？它们之间有什么区别？

MySQL 常见存储引擎有 InnoDB、MyISAM、Memory 等

其中 InnoDB 是默认引擎，支持事务、行级锁、MVCC 等，适合高并发业务
MyISAM 不支持事务，使用表锁，查询性能较高，适合读多写少场景

目前基本以InnoDB为主

### InnoDB 的行锁是怎么实现的？是锁住整行数据吗？

InnoDB 的行锁其实是锁索引记录，不是锁物理行。

- 如果 SQL 走的是主键索引，就锁主键索引上的那条记录。

- 如果走的是二级索引，会先锁二级索引记录，再锁对应的主键记录。

- 如果查询没走索引，那就退化成表锁了，因为要扫全表，所有记录都得锁。

所以，建索引不光是为了查询快，也是为了锁的粒度更细

### MyISAM 既然只有表锁，为什么还说它读性能好？

MyISAM 读性能好，主要是因为它的设计不支持事务，不用维护 undo log，也不用做 MVCC 版本链查找
读的时候直接从 B+ 树拿到数据地址，去数据文件里顺序读取就行
但这个优点建立在无并发写或写很少的前提下。一旦有写操作，表锁会把所有读都阻塞住，性能就崩了

### MEMORY 引擎数据放内存里，和 Redis 比有什么区别？

两者定位完全不一样：

维度	MEMORY 引擎	Redis
定位	MySQL 进程内存储，只能通过 SQL 访问	独立 KV 缓存/存储服务
数据结构	固定为表结构	支持多种数据结构（String、Hash、List、Set、ZSet 等）
持久化	重启即丢	支持 RDB/AOF 持久化
如果只是 MySQL 内部做临时表计算，用 MEMORY 引擎；如果是分布式缓存或独立存储场景，用 Redis

### 生产环境怎么查看当前表用的是什么引擎？

```
SHOW TABLE STATUS LIKE 'table_name';
```
查看 Engine 列即可。

```
SHOW CREATE TABLE table_name;
```
查看建表语句中的 ENGINE 参数
