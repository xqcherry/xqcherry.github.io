## MySQL索引的最左前缀匹配原则是什么？

MySQL 最左前缀匹配原则指的是联合索引查询时，需要按照索引字段的顺序从最左侧开始匹配
比如联合索引(a, b, c)，可以支持a, a+b, a+b+c查询，但不能跳过 a 直接查询 b 或 c
中间字段缺失则索引失效

### 联合索引 (a, b, c)，执行 where b = 1 and a = 2 能用上索引吗？

能用上。MySQL 的查询优化器会自动调整条件顺序，把 a = 2 放到前面，所以写成 where b = 1 and a = 2 和 where a = 2 and b = 1 效果一样

### 为什么 >= 不会停止匹配，但 > 会停止匹配?

关键在于能不能精确定位到一条记录。a >= 1 可以先精确定位到 a = 1 的第一条数据，这时候 b、c 在 a = 1 内部是有序的，可以继续匹配。而 a > 1 定位到的是 a = 2 的 n 条数据，此时已经跨过了 a = 1 的整个范围，不同 a 值之间 b、c 是无序的，所以后面的用不上索引

### 建联合索引时，列的顺序应该怎么考虑？

1. 高频查询条件放左边，保证常用查询能走索引

2. 区分度高的列放左边，能更快过滤掉数据

3. 范围查询的列放最右边，避免阻断后面的匹配

4. 如果经常有排序需求，把排序字段放到索引里，避免 filesort
