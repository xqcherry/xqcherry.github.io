## 什么是synchronized 和 ReentrantLock？

### synchronized是什么？

synchronized 是 Java 内置关键字，悲观锁机制，通过JVM监控器实现线程同步，可以修饰方法和代码块，锁的释放由 JVM 自动完成

### ReentrantLock是什么？

ReentrantLock 是 JUC包 提供的可重入锁，基于AQS实现，需要手动lock和unlock

## 两者有什么区别?

1. synchronized 是关键字，可以修饰方法和代码块；ReentrantLock是一个类，需要手动加锁解锁
2. synchronized由JVM管理，自动释放锁；ReentrantLock 需要手动释放
3. synchronized 是非公平锁，ReentrantLock 默认非公平，但支持公平锁
4. synchronized 功能简单，ReentrantLock支持公平锁，可中断锁、超时获取锁等高级功能
5. synchronized 基于 JVM 的 Monitor实现；ReentrantLock 基于AQS实现
6. JDK6 后 synchronized 进行了锁优化，两者性能差距不大，需要高级锁功能时再选择 ReentrantLock

#### 公平锁和非公平锁有什么区别？为什么默认是非公平锁？

公平锁按照线程等待的先后顺序获取锁，先来先得；非公平锁允许插队，新来的线程可以直接尝试 CAS 抢锁，抢不到再排队
默认非公平是因为性能更好，减少了线程切换开销
公平锁每次都要唤醒队列头部线程，上下文切换多，吞吐量会下降。除非业务上要求严格排队，否则用非公平锁就行

#### ReentrantLock 的 lock 方法忘记 unlock 会怎样？

锁永远不释放，其他线程全部阻塞等待，程序卡死。所以必须用 try-finally 包起来，finally 里面 unlock，保证无论正常返回还是抛异常都能释放锁，synchronized 不存在这个问题，JVM 自动管理

#### 可重入锁是什么?

同一个线程已经获取锁之后，可以再次获取同一把锁，而不会发生死锁
实现原理是锁内部记录当前持有线程和重入次数，每获取一次计数加一，每释放一次计数减一，直到计数为 0 才真正释放锁
