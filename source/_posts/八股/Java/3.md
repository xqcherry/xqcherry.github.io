## 介绍一下CAS？

CAS 是一种**乐观锁**思想, 通过比较内存中旧值是否发生变化，如果没有变化就更新，有变化就不断重试
包含三个操作数，内存位置，预期值和新值，如果内存位置V等于预期值A, 则更新为新值B


## 介绍一下AQS？

AQS 是 Java 并发包中的同步器框架，用于构建锁，同步器等
通过state变量和等待队列管理线程竞争资源
ReentrantLock等都是基于 AQS 实现的

**核心**
1. state状态
2. FIFO队列：控制线程抢锁，多线程竞争锁时，对于没抢到锁的线程，维护一个双向链表等待线程队列，锁释放时候从队列中选取合适线程占用锁
3. 实现 `acquire` 和 `require`操作

## CAS和AQS关系？
AQS 内部也会使用 CAS 来保证 state 修改的线程安全
- `acquire` 操作，当线程尝试获取资源时，会使用 CAS 操作尝试将 state 从一个值更新为另一个值，如果更新失败，说明资源已被占用，线程会进入等待队列
- `release` 操作中，当线程释放资源时，也会使用 CAS 操作将 state 恢复到相应的值，以保证状态更新的原子性
