## 向量检索和关键词检索有什么区别?



**关键词检索 ：** 它查找文档中是否出现了和你输入一模一样的“词”，通过计算词频（TF）和逆文档频率（IDF）来打分

**向量检索：** 它通过 Embedding 模型将文本转化为高维空间里的“坐标（向量）”。检索时，它寻找的是空间距离最接近的向量

区别在于关键词检索是精确匹配，用于查找特定名词，术语，而向量检索倾向于语义理解，寻找语义相近的答案



### 追问：如何选择检索方式，取决什么因素

### 1. 取决于数据的“结构化程度”

- **选关键词检索：** 如果数据包含大量**专有名词、产品型号、错误代码、人名或特定 ID**。这些词具有唯一性，错一个字意思全变，必须精确匹配。
- **选向量检索：** 如果数据是**非结构化的自然语言**（如用户评价、闲聊、长篇散文）。这种数据表达方式多样，更依赖语义理解。

### 2. 取决于用户的“查询意图”

- **选关键词检索：** 用户带有**明确的目标**。例如“查找 2023 年的财务报表”，用户需要的是包含这些特定词汇的精确结果。
- **选向量检索：** 用户带有**模糊的意图**。例如“如何让我的心情变好”，用户并不在意文档里有没有“心情”或“变好”这两个原词，只要内容符合这个意境即可。

### 3. 取决于对“同义词/泛化能力”的要求

- **选向量检索：** 当你的知识库中存在大量同义词（如“西红柿”与“番茄”、“购机”与“买手机”），或者需要**跨语言搜索**时，向量检索的 Embedding 机制能自动处理这些关联。
- **选关键词检索：** 当你需要**绝对的可解释性**时。关键词检索能明确告诉你为什么召回这条（因为匹配了某个词），而向量检索是一个“黑盒”，解释不清坐标为何接近。

### 4. 取决于“工程成本与性能”限制

- **选关键词检索：** 资源受限（仅有 CPU）、数据量极大（TB 级）、或者对延迟要求极其苛刻。开销极小
- **选向量检索：** 拥有 GPU 推理资源、具备向量数据库（如 Pinecone, Milvus）的维护能力。向量检索需要实时计算 Embedding，计算和存储成本更高。



## 你了解的tool调用机制是怎么样的?

**Tool Calling（工具调用）** 是让大模型（LLM）具备“动手能力”的机制。它让模型通过外部接口获取实时信息或执行具体任务。核心不是模型直接运行代码，而是模型决定使用什么工具，然后由后端代码解析大模型返回的json，调用真实的 API 或数据库并获取结果，将结果返回给大模型的过程

**整个过程是：**

1. 开发者将外部能力的 **JSON Schema**（名称、描述、参数约束）作为上下文喂给模型，建立模型的“技能清单”
2. 模型分析用户请求，判断需调用外部工具，并**生成结构化指令**（如 JSON），输出具体的函数名及参数
3. 模型停笔，由后端程序解析 JSON 指令，调用真实的 API、数据库或本地函数，并获取执行结果
4. 程序将执行结果回送给模型，模型结合**“原始意图 + 工具返回事实”**，进行二次推理并输出最终的自然语言回复



## 什么是Embedding，BM25，RRF?

1. embedding是向量检索，将文本转化为向量空间中的向量，语义相近的字词在向量空间中距离越近，通过计算向量空间中的向量的距离，来判断两个词的语义相似度
2. BM25是打分算法，有两个指标：1. 关键词出现的频率，2. 词的稀有度（关键词）根据这两个指标来进行关键词检索
3. RRF是合并算法，通过对文档在embedding，bm25中不同的搜索表现进行一个综合打分，来找到最符合检索需求的内容
