# 密码学基本模型与 OTP

## 密码学基本模型

密码学研究的是：

> **如何让信息在不安全的环境中安全地传输。**

一个基本的密码系统由以下几个部分组成：

* **M（Message）**：明文空间
* **C（Ciphertext）**：密文空间
* **K（Key）**：密钥空间
* **E（Encryption）**：加密算法
* **D（Decryption）**：解密算法

基本过程：

```text
明文 M
  │
  │ + 密钥 K
  ▼
加密 E
  │
  ▼
密文 C
  │
  │ + 密钥 K
  ▼
解密 D
  │
  ▼
明文 M
```

数学表示：

```text
C = E(K, M)
M = D(K, C)
```

### 正确性

一个正确的密码系统必须满足：

```text
D(K, E(K, M)) = M
```

也就是说：

> **加密之后再用正确的密钥解密，必须能够恢复原来的明文。**

---

## XOR 异或运算

OTP（一次一密）大量使用 XOR，因此需要先理解异或。


**XOR 的重要性质**

**1. 自反性**

```text
A ⊕ B ⊕ B = A
```

因为：

```text
B ⊕ B = 0
A ⊕ 0 = A
```

所以：

```text
(A ⊕ B) ⊕ B = A
```

这正是 OTP 能够用同一个密钥完成解密的原因

---

## 一次一密 OTP

OTP 全称：

> **One-Time Pad（一次一密）**


**每一位明文都使用一个真正随机、只使用一次的密钥进行加密。**


1. **OTP 加密**

    假设：

    ```text
    明文 M = 10110010
    密钥 K = 01101101
    ```

    使用 XOR：

    ```text
        10110010
    ⊕  01101101
    --------------
        11011111
    ```

    所以：

    ```text
    C = M ⊕ K
    ```

    得到：

    ```text
    C = 11011111
    ```

2. **OTP 解密**

    解密时：

    ```text
    M = C ⊕ K
    ```

    代入：

    ```text
        11011111
    ⊕   01101101
    --------------
        10110010
    ```

    成功恢复：

    ```text
    M = 10110010
    ```

    因此 OTP：

    ```text
    加密：

    C = M ⊕ K

    解密：

    M = C ⊕ K
    ```

## 为什么 OTP 能解密？

关键就是 XOR 的自反性：

```text
C = M ⊕ K
```

解密：

```text
C ⊕ K
= (M ⊕ K) ⊕ K
= M ⊕ (K ⊕ K)
= M ⊕ 0
= M
```

因此：

```text
D(K, E(K, M)) = M
```

---

## OTP 的三个核心条件

OTP 想要达到**完美保密（Perfect Secrecy）**，密钥必须满足三个重要条件：

1. 密钥必须真正随机

2. 密钥长度必须 ≥ 明文长度(完善保密性)

3. 密钥只能使用一次

只能使用一次是 OTP 最重要的条件。

例如：

```text
M1 ⊕ K = C1
M2 ⊕ K = C2
```

如果重复使用 K：

```text
C1 ⊕ C2
= (M1 ⊕ K) ⊕ (M2 ⊕ K)
= M1 ⊕ M2
```

因为：

```text
K ⊕ K = 0
```

所以密钥被抵消了。

攻击者虽然不知道 K，但可以得到：

```text
M1 ⊕ M2
```

这会泄露明文之间的关系。

因此：

> **OTP 的密钥绝对不能重复使用。**

---

## OTP 为什么具有完美保密性？

Shannon 在 1949 年提出了完美保密的概念

直观理解：

> **攻击者即使拿到了密文，也无法从密文本身获得关于明文的额外信息。**

数学表达：

```text
P(M | C) = P(M)
```

意思是：

> 已知密文 C 后，明文 M 的概率分布没有发生变化。

也就是说：

```text
看到密文之前：
攻击者认为 M 有哪些可能

看到密文之后：
攻击者仍然认为 M 有哪些可能
```

密文没有提供额外的信息。

---

## Shannon 定理

### 1. 完善保密性的基本要求

Shannon 对完善保密性进行了形式化研究。

对于一个密码系统，如果希望实现**完善保密性**，则密钥空间必须足够大。

对于等长的固定长度消息，可以记为：

```text
|K| ≥ |M|
```

其中：

* `|K|`：密钥空间的大小
* `|M|`：明文空间的大小

因此：

```text
|K| < |M|
→ 无法实现完善保密性
```

---

### 2. 为什么密钥太少不行？

直观理解：

> **密钥太少，就无法让所有可能的明文都能够产生同一个密文。**

例如：

```text
明文空间：

M = {M1, M2, M3, M4}

密钥空间：

K = {K1, K2}
```

假设攻击者得到：

```text
C = C1
```

由于只有两个密钥，可能只有：

```text
M1 + K1 → C1
M2 + K2 → C1
```

而：

```text
M3
M4
```

无法通过任何密钥产生 `C1`。

于是攻击者看到密文后，就可以排除：

```text
M3
M4
```

也就是说：

```text
看到密文之前：

M1、M2、M3、M4
都有可能


看到密文之后：

M1、M2
可能

M3、M4
不可能
```

所以密文泄露了关于明文的信息。

因此：

```text
P(M | C) ≠ P(M)
```

无法实现完善保密性。

---

## Shannon 定理与 OTP

OTP：

```text
C = M ⊕ K
```

对于任意给定的明文 `M` 和密文 `C`，都可以计算出：

```text
K = M ⊕ C
```

例如：

```text
M = 1010
C = 1101

K = M ⊕ C
  = 1010 ⊕ 1101
  = 0111
```

因此，对于同一个密文：

```text
C = 1101
```

不同的明文都可以找到对应的密钥。

例如：

```text
M1 → K1 → C
M2 → K2 → C
M3 → K3 → C
M4 → K4 → C
```

只要密钥是真正随机的，并且所有可能的密钥具有合适的概率，攻击者就无法仅通过密文判断哪个明文是真实的。

因此 OTP 可以实现完善保密性。

---

## OTP 的核心矛盾

OTP 在理论上可以实现完善保密性，但实际使用存在一个非常大的问题：

> **密钥必须和明文一样长，而且只能使用一次。**

例如：

```text
需要加密：

100 GB 数据
```

OTP 就需要：

```text
100 GB 真随机密钥
```

并且还需要把这：

```text
100 GB 密钥
```

安全地交给接收方。

于是出现一个经典问题：

> **如果已经存在一个能够安全传输 100 GB 密钥的通道，为什么不直接通过这个安全通道传输 100 GB 明文？**

这就是 OTP 的核心现实问题：

```text
OTP
 │
 ├── 理论安全性：非常强
 │
 └── 实际问题：密钥分发困难
```

---

## 从 OTP 到流密码

现代密码学希望解决：

> **能不能使用一个较短的密钥，安全地加密大量数据？**

于是出现了流密码的思想：

```text
短密钥
   │
   ▼
密钥流生成器
   │
   ▼
长密钥流
   │
   ▼
     ⊕
    / \
   /   \
明文   密钥流
   \   /
    \ /
     ▼
    密文
```

OTP：

```text
明文 ⊕ 真随机密钥
```

流密码：

```text
明文 ⊕ 伪随机密钥流
```

核心区别：

|       | OTP     | 流密码                   |
| ----- | ------- | --------------------- |
| 密钥    | 真随机     | 短密钥生成密钥流              |
| 密钥长度  | ≥ 明文长度  | 通常远小于明文               |
| 密钥使用  | 只能一次    | 依赖具体算法和 nonce/IV 使用规则 |
| 理论安全性 | 可实现完善保密 | 通常不是信息论安全             |
| 实际应用  | 密钥分发困难  | 更适合实际系统               |


> **Shannon 定理说明，实现完善保密需要足够大的密钥空间；OTP 通过“真随机、等长、一次性”的密钥满足这一要求，但密钥分发成本巨大，因此实际密码系统通常使用短密钥生成长密钥流。**
